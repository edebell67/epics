EP050 Node 27 — Structured Lead Capture

Deterministic, offline-only consented lead records. No live capture, contact, routing, network, publication, or external action.

GATE

Accept exact Node 26 routing context

Accept only a valid local Node 26 route with literal external_action: false, a credential-free HTTPS .test destination, and immutable target, opportunity, asset, CTA, source/channel, session and route lineage.

CONSENT

Validate privacy-safe intake

Require explicit consent timestamp, version and basis. Accept a bounded approved schema only; reject all plain-text email, telephone, name, address, free-text or unapproved fields. No contact information is stored.

RECORD

Build an inert deterministic record

Normalize allowed pseudonymous session data and create a stable slc_ lead identifier derived from the approved intake and Node 26 lineage. Preserve source, asset, CTA, target and destination context, consent evidence and literal external_action: false.

STORE

Persist locally with conflict protection

A caller-selected local JSON fixture repository permits idempotent replay of byte-equivalent records and rejects records that conflict on the same lead ID. It has no transport or execution adapter.

STOP

Fail closed

Reject absent/invalid consent, invalid Node 26 lineage, non-.test destinations, PII, duplicate/conflicting records, execution requests, unknown fields and any network attempt. Nodes 28–37 remain excluded.

TEST

Completion boundary

Local regression must exercise real Node 19→20→21→26→27 fixtures, valid capture, negative validation, determinism, persistence, idempotency/conflict and socket-blocked execution. Evidence remains pending allocator acceptance; Node 27 must not self-declare 100%.
