EP047 · data-quality and verification readiness

Validate fields first. Verify businesses second.

This workflow separates factual data quality from owner verification. A record earns a status from field rules; batch verification then follows an explicit policy for that status.

A pipeline column is not validation.Validation is a repeatable rule engine with per-field results, clear record outcomes, repair work, and an auditable decision on whether the record may enter verification.
1

Configure field rules

Admin-controlled schema per business type/source.

  • Set mandatory fields, e.g. business name.
  • Set type/format rules: phone, email, date, URL, postcode.
  • Set allowed values, length, country/region rules.
  • Version every rule change.
2

Import and normalise

Retain the source value and produce a normalised working value.

  • Trim/case-normalise.
  • Resolve column aliases.
  • Preserve source/provenance.
  • Never silently overwrite a source value.
3

Run field validation

Run the same deterministic rules at scale for every record.

  • Mandatory present?
  • Correct data type?
  • Correct format?
  • Valid allowed value/range?
  • Duplicate/conflict check?
4

Classify record

Calculate status from every field result—never manually guess it.

  • Non-valid: any mandatory field blank/invalid.
  • Partially validated: mandatory fields valid; repairable non-mandatory issue remains.
  • Validated: all required quality rules pass.
5

Repair queue

Invalid values become targeted work—not an unstructured manual hunt.

  • Group by issue: bad phone, invalid email, missing postcode.
  • Research a replacement value.
  • Store proposed value and evidence.
  • Re-run validation after correction.
6

Verification eligibility

Policy decides which validated state can enter a secure batch.

  • Non-valid: never eligible.
  • Validated: eligible.
  • Partially validated: policy choice.
  • If allowed, owner sees highlighted fields needing confirmation.
Non-valid

Blocked from verification

At least one mandatory field is blank or invalid—for example, no business name, or a mandatory contact field that fails its required format rule.

Next action: repair/research queue, then re-run all rules.

Partially validated

Policy-controlled

All mandatory fields pass, but one or more repairable fields fail—such as malformed phone, optional website, or optional date.

Next action: repair first, or permit verification with those exact fields visibly flagged to the owner.

Validated

Ready for verification

Mandatory fields are present and valid, all configured quality rules pass, and no blocking record-level issue remains.

Next action: may appear in the secure multi-business verification batch picker.

Scale operation

  1. Run the validation engine against all imported and changed records.
  2. Place failures into issue-specific repair queues.
  3. Apply evidence-backed corrections in bulk or per record.
  4. Re-run validation automatically after each correction.
  5. Expose only records meeting the current eligibility policy to batch preparation.
  6. On partial policy inclusion, inject a clear owner-facing “please check this field” highlight into that record’s secure form.
