Generation module workflow

The deferred black box, now specified: a Render cron job runs a Python loop every 5 minutes, checks the generation queue, and for each waiting business calls a configured LLM/agent (model-agnostic — no vendor lock) using the ep044_group skill library and the shared image library, then commits the built site to ep_044_web_apps on GitHub and reports completion back. Four prerequisites are genuinely outstanding — three of them are hosting/data gaps found by inspecting the repo, not design choices.

Already built and live-tested: the queue, complete and notify endpoints, with bearer-key auth — verified by real HTTP calls against a real database. The generation module only ever talks to the app through those three, so it can be built and replaced without touching anything else.
