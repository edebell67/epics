EP050 — Distribution Engine master workflow

Top-down, automated architecture map for a standalone demand-to-outcome engine. It captures the master specification’s 37 logical nodes as seven executable process boundaries, each executing deterministically and programmatically end-to-end. Status reflects genuine node acceptance, not aspirational readiness.

Safety boundary. This map defines an automated, programmatic pipeline end-to-end: every accepted node executes deterministically with no human manually keying data in the loop. It does not by itself authorize live scraping, posting, outreach, publishing, lead routing, payment, or any external network action beyond what each node's own accepted implementation explicitly supports. Nodes 05-10's live demand-data acquisition is a CORE REQUIREMENT: as of 2026-08-17 all six nodes have a real, tested automated-fetch implementation, gated off by default until the user opts in and (for 4 of the 6) supplies API credentials -- see the Demand discovery child map for exactly which.

Configuration & Master Data — required for scale

Cross-cutting, not a phase

Added 2026-08-19 after de-hardcoding swept the pipeline: every place a node used to assert a specific town, trade, cost or claim as a literal, it now either derives from real upstream data or fails closed. That removed the fabrication, but it also means the pipeline currently knows almost nothing about the world beyond what one campaign's own signal tells it -- it has no independent source for postcodes, adjacent geography beyond one hand-curated list, real cost rates, or verified business claims. Scaling to many campaigns needs these captured as real, owned, versioned master data -- not invented per-request, and not re-hardcoded as a "fix". Dashed/purple = not yet built as a genuine config space, matching the Planned lane's convention.
