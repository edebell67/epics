## Risks/Notes
- **on_screen_text is silently unused by design.** Node 18 scenes carry an `on_screen_text`
  field; EP048's pipeline auto-generates burned-in captions from the narration audio itself and
  has no separate slot for supplied on-screen text. This is a real, permanent format mismatch
  between the two systems documented in the adapter's docstring, not a bug to fix later --
  fixing it would require changing EP048's caption-generation design, which is out of scope and
  not this agent's system to modify.
- **The render trigger remains unbuilt, deliberately.** Calling `generate_video.py` spends real
  money (ElevenLabs, and potentially Pexels/Higgsfield rate limits) and produces a real video
  file. EP050's own master spec requires an approval/rights gate and explicit external-action
  authorization before that step; this agent's standing operating constraints separately require
  not triggering paid external generation unattended. Both point the same direction: this stays
  a manual, explicitly-authorized action for now.
- **The backward hand-back (EP048 render result -> EP050) has no landing spot yet.** The natural
  home is Node 19 (Quality & Compliance), which sits between asset creation (Node 18) and
  distribution (Phase 5) in the master spec -- but Node 19 has zero implementation today, and it
  is not in this agent's allocated node range (Gemini-owned per prior board activity). Building
  the hand-back depends on Node 19 existing first, and building Node 19 is not this agent's call
  to make unilaterally.
- EP048's own automation claim was independently verified as genuine in this task, in contrast
  to several other same-day findings in this project where "100% automated" claims from other
  agents turned out to be false or overstated. Worth remembering for future EP048-related work:
  this codebase does not carry that same risk pattern.
