## Risks/Notes
- **Real bug found and fixed during first test run**: the initial idempotency comparison excluded only `recorded_at`, but `CampaignClusterRecord.created_at` is also freshly stamped per build, causing an identical re-clustering rerun to be misclassified as a conflicting duplicate (`ConflictError` instead of returning the existing record). Fixed (v1.0.1) by excluding both timestamp fields from the comparability check. This lesson (timestamp fields must be fully excluded from identity comparisons, not just the most obvious one) is carried forward for any future clustering/aggregation node.
- `cluster_id` is a pure function of member content (SHA-256 of sorted `selection_id`s + rule version), so a genuine conflicting-duplicate cannot be produced through the public API alone; the conflict test deliberately tampers stored JSON to simulate a legitimate external-edit conflict scenario, documented inline in the test.
- The suite imports Node 11-14's real modules directly (via `sys.path` insertion) rather than duplicating or mocking their logic; Nodes 11-14 are Gemini-owned and were not modified.
