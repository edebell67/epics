Automation

Built once.
Runs on its own.

The point of most of what we build is that it keeps working after we stop touching it. These are the processes that start themselves, on a schedule or a signal, check their own output and leave a record. Each one links to the process map it was built from.

  1. 01 · TriggerStarts itselfA schedule, an interval or an event, never a person remembering.
  2. 02 · GateChecks inputsBad or implausible input is rejected before anything is spent.
  3. 03 · RunBounded workLimited scope, limited concurrency, safe to repeat.
  4. 04 · VerifyPass or failAn explicit result with a reason, stored durably.
  5. 05 · RecordLeaves a trailLogged, auditable and visible to whoever owns it.

The queue endpoint is authenticated and internal-only, and recovery requires an explicit reason, a row lock and an audit entry.

A monitor watches the forex and crypto price endpoints. If either goes stale for more than two minutes or stops responding, it restarts the price server on its own.

The threshold and restart command live in configuration, not code, so the rule is visible and adjustable.

Exactly once

Ledgers and idempotent endpoints mean a job that runs twice does the work once.

Nothing public by default

Imports land as drafts. Publishing, sending and deploying need an approved policy or explicit sign-off.

Explicit failure

Runs end in a pass or a named failure, never a silent stop.

Evidence, not claims

Every map node has a completion test. The checklists hold the evidence.
